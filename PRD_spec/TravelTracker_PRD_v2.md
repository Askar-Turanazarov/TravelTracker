## 1. Executive Summary & Business Context

### 1.1. Визия и Проблематика
Большинство существующих сервисов учета поездок страдают от одной из двух крайностей: они либо представляют собой сложные планировщики с перегруженным функционалом, либо являются закрытыми социальными сетями. Пользователю-путешественнику нужен минималистичный, эстетичный и приватный инструмент для решения одной главной задачи: визуализировать свой географический опыт на карте и видеть точную статистику освоения мира.

### 1.2. Бизнес-цели и ROI (Value Proposition)
**Цель учебного/портфолио-проекта:** Продемонстрировать навыки построения production-ready full-stack сервиса, сочетающего реляционную архитектуру, жесткую валидацию международных стандартов (ISO), интеграцию геопространственных карт (Leaflet.js) и эффективную реактивную сборку.
**Бизнес-ценность:** Максимальный ROI за счет минимальных затрат на разработку ($TTM = 5\text{ дней}$) при высоком визуальном «ВАУ-эффекте» для ревьюеров.

### 1.3. График реализации (Roadmap MVP)
**Фаза 1 (Дни 1–2):** Проектирование схемы БД, настройка backend (CRUD, JWT auth, ISO-валидация).
**Фаза 2 (Дни 3–4):** Разработка UI (React + Tailwind CSS + Leaflet.js), настройка темной темы.
**Фаза 3 (День 5):** Интеграция API, обработка edge-cases, тестирование производительности рендеринга карт и релиз.

## 2. Метрики Успеха (KPIs & Telemetry)

### 2.1. Продуктовые метрики
**North Star Metric:** Количество успешно сохраненных локаций (`Trips Logged`) на пользователя.
**Time-to-First-Pin (TTFP):** Время от первого входа в систему до создания первого пина на карте $< 30$ секунд.
**Completion Rate:** Доля успешно заполненных и сохраненных форм добавления поездки $> 95\%$.

### 2.2. Инженерные метрики (SLO / Performance)
**API Response Time ($p_{99}$):** Response time для всех CRUD-запросов $< 150\text{ms}$.
**Initial Map Render Time:** Первичная инициализация карты с рендерингом до 100 маркеров $< 500\text{ms}$.
**Cumulative Layout Shift (CLS):** $CLS < 0.05$ при загрузке карты.
**Bundle Size (Gzip):** Общий размер JavaScript/CSS бандла на клиенте $< 350\text{KB}$.

### 2.3. План Телеметрии и Событий (Event Tracking Matrix)

| Название события | Триггер (Условие срабатывания) | Payload (Передаваемые данные) |
| :--- | :--- | :--- |
| `auth_login_success` | Успешный вход пользователя | `{ user_id, method: "jwt" }` |
| `trip_create_initiated` | Открытие модального окна добавления | `{ source_button: "header" \| "map_context" }` |

| `dashboard_filter_changed` | Применение фильтра в списке | `{ filter_type: "rating" \| "country", value }` |

## 3. Целевая Аудитория и Ролевая Модель (RBAC)

### 3.1. User Personas
**Casual Traveler:** Любит ездить в отпуск 2-3 раза в год. Хочет красиво оформить свои поездки и вести визуальный список.
**Digital Nomad:** Менят страны каждые 1–3 месяца. Ему критически важен точный учет городов, дат посещения и заметок о качестве жизни.
**Portfolio Evaluator:** Оценивает качество архитектуры, устойчивость к ошибкам ввода и скорость работы интерфейса.

### 3.2. Матрица Доступов (RBAC)

## 4. Детализированные Функциональные Требования (BDD Format)

### Модуль 1: Аналитический Дашборд (FR-DASH)

**FR-DASH-1: Расчет агрегированных метрик**
Описание: В верхней части главного экрана отображаются три ключевые аналитические карточки.
**Формула «Посещено стран»:** $$C_{unique} = \text{COUNT(DISTINCT } country\_code \text{)}$$
**Формула «Процент освоения мира»:** $$P_{world} = \left( \frac{C_{unique}}{195} \right) \times 100$$
**Формула «Посещено городов»:** $$N_{cities} = \text{COUNT(DISTINCT } city\_name \text{)}$$

**Acceptance Criteria (BDD):**
**Given:** авторизованный пользователь с 12 уникальными странами и 28 городами в БД.
**When:** пользователь загружает главную страницу.
**Then:** плашка «Посещено стран» показывает `12`, «Прогресс мира» показывает `6.2%`, «Городов» показывает `28`.

---

### Модуль 2: Интерактивная Гео-карта (FR-MAP)

**FR-MAP-1: Инициализация и тайлы карты**
Описание: Карта занимает основной экран приложения и использует темную эстетическую подложку CartoDB Dark Matter.

**Acceptance Criteria (BDD):**
**Given:** пользователь открывает приложение.
**When:** компонент карты монтируется в DOM.
**Then:** клиент инициализирует Leaflet.js с тайл-сервером `https://{s}.basemaps.cartocdn.com/dark_all/{z}/{x}/{y}{r}.png`.

**FR-MAP-2: Рендеринг маркеров и Auto-Bounding Box**
Описание: Каждая запись рендерится в виде светящегося пина по координатам. Карта автоматически масштабируется под географию пользователя.

**Acceptance Criteria (BDD):**
**Given:** у пользователя есть поездки в Токио и Рим.
**When:** карта заканчивает загрузку данных.
**Then:** на карте отрисовываются 2 интерактивных маркера, а карта автоматически вызывает `map.fitBounds()`, чтобы оба пина были полностью видны.

**FR-MAP-3: Интерактивный попап карточки**
Описание: Клик по маркеру открывает кастомный стилизованный попап с деталями визита.

**Acceptance Criteria (BDD):**
**Given:** на карте отображен маркер города «Дананг».
**When:** пользователь кликает на маркер.
**Then:** открывается всплывающее окно, содержащее флаг-эмодзи, название, дату визита, оценку, заметку и кнопки редактирования.

---

### Модуль 3: Управление Поездками / CRUD (FR-CRUD)

**FR-CRUD-1: Валидация и создание поездки**
Описание: Создание поездки происходит через модальное окно с жесткой валидацией полей.
**Список полей формы:** `country_code` (обязательное), `city_name` (обязательное), `visited_date` (обязательное), `rating` (обязательное), `lat` и `lng` (обязательное), `notes` (опционально).

**Acceptance Criteria (BDD):**
**Given:** открыта форма создания поездки.
**When:** пользователь заполняет все поля корректными данными и нажимает «Сохранить».
**Then:** отправляется POST-запрос, при ответе `201 Created` модальное окно закрывается, дашборд обновляется, карта плавно анимирует перелет к новым координатам.

**FR-CRUD-2: Geocoding Fallback**
Описание: Если пользователь ввел город и страну, но не указал координаты, система должна использовать внутренний fallback.

**Acceptance Criteria (BDD):**
**Given:** пользователь оставляет поля координат пустыми.
**When:** форма отправляется на бэкенд.
**Then:** бэкенд ищет координаты во внутреннем JSON-справочнике центроидов и подставляет их, возвращая успешный статус сохранения.

## 5. Полная Матрица Исключений и Edge Cases

| Сценарий / Сбой | Механизм обнаружения | Поведение системы (Graceful Degradation) |
| :--- | :--- | :--- |
| **Недоступность тайлов** | Ошибка сети или timeout $> 3000\text{ms}$. | Карта переключается на запасной бесплатный OpenStreetMap tile-сервер. Выводится Toast уведомление. |
| **Ввод даты из будущего** | Валидатор HTML5 + схема на бэкенде. | Кнопка «Сохранить» заблокирована. Выводится ошибка: *"Дата поездки не может быть в будущем"*. |
| **Отсутствие интернета** | `navigator.onLine === false`. | Форма сохраняет введенные данные в `localStorage`. |
| **XSS-атака через заметки** | Ввод скрипта в `notes`. | Бэкенд экранирует и санитизирует HTML-сущности. |
| **Создание дубликата** | Уникальный индекс в БД. | Сервер возвращает `409 Conflict`. Выводится сообщение об ошибке. |

## 6. Нефункциональные Требования (NFR)

### 6.1. Производительность (Performance & Scale)
**Concurrent Users:** Поддержка до 100 одновременных активных сессий без деградации времени отклика.
**Map Marker Clustering:** Автоматическая кластеризация маркеров при наличии более 150 локаций.
**Database Indexing:** Обязательное наличие B-Tree индексов для выполнения агрегационных SQL-запросов за время $< 10\text{ms}$.

### 6.2. Безопасность и Стандарты (Security & Compliance)
**Аутентификация:** Stateless JWT. Access Token живет 15 минут, Refresh Token хранится в `HttpOnly, Secure, SameSite=Strict` Cookie.
**CORS Policy:** Явное ограничение запросов только с разрешенного домена клиента.
**Rate Limiting:** Общие запросы — 100 req/min, Создание/Удаление — 20 req/min.

### 6.3. Совместимость и Мобильность
**Cross-browser:** Работает в Chrome, Safari, Firefox, Edge.
**Responsive Layout:**
**Desktop ($\ge 1024\text{px}$):** Сплит-экран (слева — панель управления, справа — карта).
**Mobile ($< 768\text{px}$):** Таб-бар переключения между режимами «Карта», «Список», «Аналитика».
